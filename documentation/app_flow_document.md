# IELTS Test Application App Flow Document

## Onboarding and Sign-In/Sign-Up
A new user first arrives at the IELTS Test Application landing page, which clearly presents options to sign up or log in. Choosing to create an account, the user is taken to a sign-up form where they enter their email address, choose a password, and confirm terms of service. Once submitted, a verification email is sent. The user clicks the link in that email to confirm their account and returns to the app. Alternatively, a user can sign up using social login providers such as Google or Facebook. When selecting social login, a popup window prompts them to grant access and then redirects them back to the application with their profile created automatically. Existing users select the sign-in link, enter their credentials, and click the login button to reach the home page. If a user forgets their password, they click the “Forgot Password” link, provide their registered email address, and receive a reset link by email. Following that link takes the user to a secure reset page where a new password can be entered and confirmed. Once set, the user can log in with the updated credentials. At any time, the user can sign out by clicking the “Logout” button in the navigation bar, which clears their session and returns them to the landing page.

## Main Dashboard or Home Page
After logging in, the user lands on a dashboard tailored to their role. A student sees a welcome banner with their name and progress summary for assigned courses. Below the banner, lessons and practice quizzes appear as tiles they can click to begin or continue. A vertical navigation panel on the left lists links to Courses, Quizzes, Reports, and Profile settings. The header displays a notifications icon and a menu for account options, including logout. Administrators see a different dashboard. They view quick-access cards for managing Courses, Lessons, Quizzes, and Users. A sidebar on the left shows links to Course Management, Quiz Administration, Placement Tests, Reports, and Settings. Both students and admins can navigate to other areas by clicking these links, and the main area updates dynamically without a full page reload, thanks to Livewire components.

## Detailed Feature Flows and Page Transitions
When an administrator clicks “Course Management,” they arrive at a page listing all courses. Each course row has buttons to edit or delete. Creating a new course opens a form where the admin enters the course title, description, and image. A rich text editor (TinyMCE) appears for detailed course content. Once the admin saves, the page transitions back to the course list and shows the new entry. Selecting a course leads to its lesson list. Clicking “Add Lesson” opens a similar editor where the admin defines lesson modules and uploads media. Saving returns to the lesson list with the new lesson visible.
For quiz creation, the admin clicks “Quiz Administration” and sees all quizzes displayed. Choosing “New Quiz” opens a form to name the quiz, set time limits, and add questions. Adding a question triggers a modal where the admin picks the question type (multiple choice, fill-in-the-blank, matching, or essay) and fills in the prompt and answers. The admin can preview the question instantly to verify formatting and logic before saving. After the quiz is published, it appears in the quiz list and can be assigned to specific courses or student groups.
Students navigate from the dashboard to “Placement Test” to start an initial assessment. The test page automatically loads questions one at a time. As the student submits answers, the difficulty adjusts dynamically. Upon completion, the system calculates a proficiency level and displays it, then automatically enrolls the student in the matching starter course. From that result page, the student can click “Go to Course” to begin lessons.
When students access a lesson, the lesson page shows content blocks—text, images, and embedded audio. They use playback controls to listen to sample recordings and can record their own voice directly on the page. Clicking the record button opens a small widget, and when the student stops, the recording is saved and displayed for playback. Students move between lessons by clicking “Next” or “Previous,” or return to the course overview via a breadcrumb link at the top.
As students take quizzes, each question appears on its own screen with a timer in the header. After submitting each question, immediate feedback highlights correct or incorrect answers. At the end of the quiz, a results page shows the score, time taken, and suggested review materials. Students can click “Review Answers” to see detailed corrections or return to the dashboard with a single button.
Administrators monitor performance by clicking “Reports.” They see interactive graphs of average scores, completion rates, and time spent. Clicking on any chart filters the report by date range or user group. A button labeled “Export CSV” triggers a background job that generates the file. Once ready, a notification appears, and the administrator downloads the report from the notifications panel.

## Settings and Account Management
Users access their personal settings by clicking their avatar in the header and selecting “Profile.” On the profile page, they update name, email, and password. Changing the email prompts a verification email to confirm the new address. Under “Preferences,” users toggle email notifications for quiz results, course updates, and promotional messages. Settings changes save with a click, and a success message appears at the top. Administrators also have a “Billing” section under Settings, where they view subscription plans and update payment methods. Entering new card details and confirming them updates the billing account, and the new plan is applied immediately. After updating any account or subscription setting, users click “Back to Dashboard” to resume normal use.

## Error States and Alternate Paths
If a user submits invalid data during sign-up—for example, an email in the wrong format or a weak password—inline error messages appear under each field explaining the issue. On network failure, a full-screen message displays “Connection Lost” with a retry button that attempts to restore connectivity. If a student tries to access an admin-only page, the system shows a “403 Forbidden” page with a link back to the dashboard. When an admin deletes a course that still has enrolled students, a confirmation dialog warns of data loss. If an unexpected server error occurs, a friendly error page appears informing the user that something went wrong and that the team has been notified. A “Retry” button attempts the previous action again, and a “Contact Support” link opens an email form prefilled with the error details.

## Conclusion and Overall App Journey
From landing on the sign-up page through verifying their email, users quickly enter the app and find a dashboard tailored to their role. Students complete a placement test, which places them in a course, and they move from lessons to interactive quizzes and audio practice. Administrators create and manage courses, quizzes, and users, and track performance through detailed reports. Account settings and billing are always within reach, and robust error handling ensures users receive clear feedback or alternate paths when things go wrong. This cohesive flow supports a seamless experience for both learners and administrators as they prepare for the IELTS exam and manage the platform’s content and users.
